## Parameter & UV Domain Notes

### UV Domain Convention (Two Systems in Use)
The codebase uses two incompatible UV conventions. Do not mix slider values across categories.

| Convention | Categories | uMax / vMax Setting | Notes |
|---|---|---|---|
| **Literal** | Basic shapes, Minimal Surfaces, Non-Euclidean | `uMax = 2π ≈ 6.28`, `vMax = π ≈ 3.14` | Equations use u/v directly as angles |
| **Normalized** | Quantum, Medical, Higher-D, Advanced Physics | `uMax = 1.0`, `vMax = 1.0` | Equations multiply internally by 2π or π |

Setting `uMax=1` on a literal-convention shape (e.g. Sphere) produces only a 1-radian arc. Setting `uMax=6.28` on a normalized shape (e.g. Bloch Sphere) creates severe self-intersection.

### Degenerate Default Warnings
The following shapes require specific parameter values to render meaningfully:

- **`virtual_particles_uncertainty`** — collapses to near-flat geometry when noise parameter `j` is set to 0. Default `j ≥ 0.3` required for visible structure.
- **`cosmic_strings_topology`** — becomes visually invisible at high values of `f` (frequency). Keep `f ≤ 5` for a recognizable string network.
- **`p_orbital_x`** — loses the characteristic dumbbell shape when `e = 0`. Requires `e ≥ 0.5` to separate the two lobes.
- **`decoherence_evolution`** — T1/T2 defaults (50000/25000) are in microsecond-equivalent units; setting `a` or `b` below 100 makes decay too fast to observe in a single frame.
- **`quantum_fourier_transform`** — with `a > 5` qubits the N=2^a grid exceeds segment density, producing aliasing. Keep `a ≤ 4` for clean visualization.
