✅ What/Why/Where context (matches your sitemap metadata)

Implementation Strategy for Your Server
Looking at your server logs, you need to:
1. Create Content Routes Separate from Tool Routes
javascript// Content pages (SEO-optimized)
app.get('/shapes/:shapeId', renderShapeLandingPage);
app.get('/quantum/:algorithmId', renderQuantumLandingPage);
app.get('/lattices/:structureId', renderLatticeLandingPage);

// Tool/API routes (keep existing)
app.get('/tool/shapes/:shapeId', renderShapeTool);
app.get('/api/shapes/:shapeId', shapeAPI);
2. Populate Landing Pages from Your Database
Your server already has shape definitions and metadata. Use that to generate landing pages dynamically:
javascript// From your shape database
const shapeData = await db.getShape(shapeId);

// Render with template that includes:
// - Description (for SEO)
// - Technical details

3. Fix Your Sitemap Generation
Your sitemap should point to landing pages, not tools:
xml<!-- Good -->
<url>
  <loc>https://uuon-foundation.com/shapes/sphere</loc>
  <desc>Perfect Sphere - Mathematical Properties and Applications</desc>
</url>

<!-- Bad -->
<url>
  <loc>https://uuon-foundation.com/tool?shape=sphere</loc>
</url>
4. Implement Modal/Portal for Tools
When someone clicks "Generate 3D Model" on a landing page:

Opens modal overlay with your tool
URL stays on landing page (good for SEO)
User can close and return to reading
Or: Opens in /tool/shapes/sphere in new tab
